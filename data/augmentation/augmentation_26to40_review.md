## Dataset Quality Concerns

- These sources are law-firm **application** answers (motivations, commercial awareness, competencies, firm-choice), not doctrinal IRAC problem questions. Keep them in a task-specific LoRA split rather than mixing blindly with black-letter law data.
- IRAC / principle / formal-exam variants are adapted application-style structures (issue framing + evaluation criteria + application of experience), not statute/case analysis.
- Several sources contain OCR redactions (`[redacted]`, `[city]`, `x firm`, Associate/Trainee `x`). Synthetics must keep placeholders; do not fill them before training.
- Firm mix is broad (Fieldfisher, Trowers & Hamlins, CRS, HFW, Ashurst, Norton Rose Fulbright, Stephenson Harwood). Prefer firm-tagged splits if training a single motivation adapter.
- Answer 26 is character-limited (~800 characters); variants are intentionally compact.
- Answer 36 and Answer 39 are long personal statements; concise variants still need to retain key named anchors and metrics.
- Validation is model-assisted plus light parent checks. Human spot checks are still needed before training use.

## Recommendations Before Scaling Beyond 26–40

- Keep range-specific output names (`26to40`) rather than the prompt template’s stale `first5` paths.
- Human-review at least one accepted variant per source and every `paraphrased_question_model_answer` before LoRA training.
- Add automated placeholder checks for all redacted tokens present in each source (not only Answer 27/30).
- Consider a schema checker that enforces exactly 10 example types per source and boolean validation fields.
- Continue retaining `per_answer/` intermediates for audit even when the merged rejected file is empty.
- Next batch (41–50) can reuse `_merge_26to40.ps1` patterns with updated anchors.
