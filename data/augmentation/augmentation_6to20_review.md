## Dataset Quality Concerns

- The source answers appear to be application-style legal/commercial awareness answers rather than doctrinal problem questions in every case, so the generated examples should be kept in a task-specific training split rather than mixed blindly with black-letter-law IRAC data.
- Some source answers contain repetition or broad commercial claims. The generated variants reduce repetition, but the underlying factual assumptions and conclusions remain constrained by the source material.
- Validation was strict on structural fidelity, issue preservation, fact preservation, authority hallucination, and usefulness, but it remains model-assisted validation and should receive human sampling before scaling.
- No original Markdown files were modified; source paths in the JSONL point back to the original untracked Markdown directory.

## Recommendations Before Scaling

- Rename prompts and output paths consistently for each range, e.g. use `6to20` rather than stale `first5` labels.
- Add a deterministic augmentation script or schema checker so future batches can be regenerated and validated without relying on manual JSONL assembly.
- Human-review a sample across accepted outputs, especially paraphrased-question variants, before using the dataset for LoRA fine-tuning.
- Keep rejected records available for audit rather than deleting them, even when the rejection count is zero.
- Track source provenance and range boundaries in filenames to avoid merging overlapping pilots.
